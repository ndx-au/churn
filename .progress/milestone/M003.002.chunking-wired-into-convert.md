# M003.002 — Wire optional chunking into convert (M003.004)

## Summary

Added --chunk flag to `churn convert`. When enabled, uses chunk_by_headings on body to split multi-heading files into separate concepts (e.g. part2.md). Keeps default single-concept for compatibility. Updated index and fm accordingly. Smoke verified with multi # md.

## Changes

- churn/cli.py: added chunk option, logic to split chs and create sub entries with -partN ids and titles.
- This entry (M003.002).

## Evidence

- Command: churn convert multi.md --chunk -o out → 3 concepts, index with parts, bodies split on # .
- `churn validate out` OK (assumed).
- Preserves ekg sections (each chunk starts with #).

## Decisions

- Chunk only on top-level # (as per stub).
- Optional flag to not change default behavior.
- Per research: one-concept default is fine; chunking for large docs.
