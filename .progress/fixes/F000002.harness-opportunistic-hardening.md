# Fix — Harness-driven opportunistic hardening pass

## Summary

Systematic codebase audit via harness maintenance workflow: fixed silent failures in `convert`, chunking data loss, driver security gaps, and validation UX. Added 12 integration/hardening tests (35 total passing).

## Changes

- **CLI `convert`**: real progress during fetch/convert; `driver:query` dispatch; `--limit` / `--s3-anonymous`; non-zero exit on empty/missing sources; `try/finally` driver cleanup; HTTP concept ID dedup via hash; chunk part paths preserve subdirs; `manifest.json` output; `map_metadata` wired into frontmatter
- **`validate`**: removed spurious `Validate error: 1` on intentional `typer.Exit`
- **`extract`**: chunk-before-truncate; `chunk_by_headings` merge overflow; unstructured chunks emit `#` headings
- **Drivers**: FS skip `.git`/cache dirs + root boundary check; HTTP streaming size cap + retry only 5xx/429; S3 URI validation + surfaced errors + Content-Type mime; external plugins cannot override built-ins
- **OKF writer**: path traversal guard on `write_concept`; validate reports missing `index.md`; symlink-safe bundle walk
- **Tests**: `test_cli_convert.py`, `test_hardening.py`, chunk-before-truncate test
- **pyproject**: `typer[all]` → `typer` (deprecation warning fix)

- Item limit remains default 100 but is surfaced in summary/log when truncated
